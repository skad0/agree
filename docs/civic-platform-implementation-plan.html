ГипотезаЧто проверяет MVP

Граждане готовы: поддержать требования → отправить персональное обращение партии → распространить кампанию → передать полученный ответ. Платформа не мониторит политиков и не гарантирует ответ — она создаёт массовый, измеримый, публичный запрос.

приложениеedgeхранилища и сервисы

РешенияКлючевые фиксации

SQLite — обязательные PRAGMA

PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

Одно соединение на запись, короткие транзакции. Бинарные файлы в БД не хранятся.

Кэширование Cloudflare

  • Кэшируем: публичные GET-страницы, статику
  • Никогда: POST, подтверждение email, админка, персонализированные результаты, формы с чувствительными данными

Счётчики на публичных страницах — с TTL кэша, не realtime.

Cloudflare Access — периметр админки

  • Access-приложение на /admin/*: allow-list email админов, вход через SSO с принудительной 2FA — закрывает требование PRD о двухфакторной аутентификации
  • Обязательная JWT-валидация на origin: middleware Hono проверяет Cf-Access-Jwt-Assertion (jose · JWKS <team>.cloudflareaccess.com · кэш ключей · проверка aud); нет валидного токена → 403
  • Причина: origin *.onrender.com достижим напрямую — без проверки JWT Access обходится
  • Своя auth-подсистема не строится: admins = email + роль; email из JWT → admin_id → audit log
Масштаб до 1 млн сторонников достигается кэшем на edge + SQLite/WAL — без смены архитектуры. Redis, очереди и PostgreSQL сознательно исключены из MVP.

ИнвариантыПравила данных

Основной сценарийОт визита до переданного ответа

  1. Вход и языкГлавная → выбор языка (cookie) → краткое объяснение и требования кампании
  2. «Поддержать»Email + согласие с privacy policy + Turnstile; опционально имя, город, профессия, разрешение публиковать имя
  3. Подтверждение emailПисьмо со ссылкой → verify → только теперь счётчик сторонников +1
  4. Выбор адресатаПартия или политик (только с официальным публичным контактом)
  5. Сборка обращенияВыбор вопросов + опционально имя, город, короткий личный контекст, язык обращения
  6. ПредпросмотрТема email + тело + короткая версия для WhatsApp; возврат к редактированию
  7. Действиеmailto: · WhatsApp deep link · копирование темы/текста — каждое логируется отдельно
  8. «Я отправил»Самостоятельная отметка → страница результата + кнопки распространения (WhatsApp, Telegram, Facebook, ссылка)
  9. Передача ответаФорма: адресат, дата, канал, текст, файл (JPG/PNG/WebP/PDF ≤10 MB), email, согласие → очередь модерации
Переход к email/WhatsApp ≠ доказанная отправка. Публичные показатели строго раздельны: поддержали / сформировали / сообщили об отправке / передали ответ.

Хранение переводов

  • Короткий UI → JSON-словари
  • Длинные тексты кампании → Markdown
  • Шаблоны обращений → локализованные версии в БД/файлах
  • Политические и юридические тексты — только после человеческой проверки
Нет утверждённого перевода → страница не подменяет язык незаметно.

Правила RTL/LTR

  • <html lang dir> на каждой странице
  • Cookie языка; переключение → эквивалентная страница
  • Только logical properties: margin-inline, padding-inline, inset-inline, text-align:start
  • Email, URL, телефоны — в изолированном LTR-контексте (bdi / dir="ltr")

ЗащитаБезопасность и приватность

Безопасность

  • Cloudflare Turnstile на всех публичных формах
  • Rate limiting + лимит размера тела запроса
  • CSRF, secure/httpOnly cookies, строгая CSP
  • Проверка типов загружаемых файлов
  • Админка за Cloudflare Access (SSO + 2FA) + JWT-проверка на origin + audit log
  • Быстрое отключение любых пользовательских форм

Приватность

  • Минимум персональных данных; электоральный выбор не собираем без отдельной необходимости
  • Индивидуальные данные не публикуются без согласия
  • Механизм удаления данных пользователя
  • Privacy policy на всех 6 языках
  • Файлы и письма — только HTTPS
  • Публичная статистика отделена от персональных записей

ДоступностьWCAG 2.1 AA

  • Полное управление клавиатурой, видимый focus
  • Семантический HTML, настоящие labels
  • Сообщения HTMX через aria-live
  • Skip link, корректные заголовки
  • Без горизонтального overflow на 320 px
  • Lighthouse Accessibility ≥ 95
  • axe-core: 0 critical / serious

BackupРезервное копирование

  • Ежедневный внешний backup SQLite, хранение ≥ 7 копий + отдельный weekly
  • Документированная процедура восстановления, протестированная до запуска
  • Экспорт критических таблиц в CSV/JSON
  • Snapshots Render — не единственный механизм
