# Prototype data coverage map

Status is based on the checked-in source and migrations, not on the prototype’s example values. “Safe addition” means a possible next step that does not store personal appeal text or create an unverified political claim. The redesign is the default application state deployed normally, with ordinary deployment/git rollback rather than a retained legacy UI or campaign feature gate. Implementation still proceeds in stages: begin with one recipient and expand only after recipient provenance, wording, and delivery-claim gates pass.

## Migration/data gates

Before adding recipient filters or group defaults, obtain an authoritative source and define the taxonomy, default rule, freshness/snapshot date, provenance shown to users, locale coverage, inactive-history handling, and admin correction/audit behavior. A migration must not turn prototype examples into facts. The first rollout supports one recipient; multi-recipient/group delivery is a later gate, not an implied capability of the prototype.

Any schema work is additive and backwards-compatible: add (only when approved) recipient taxonomy/group membership with source/effective dates, localized metadata where available, and bounded operational selections. Keep existing IDs, routes, public IDs, retention indexes, and old rows valid; use nullable fields; make ordinary deployment/git rollback possible; add no personal-draft column. Do not persist draft text in database, URL/query/fragment, cookie, localStorage, sessionStorage, logs, analytics, audit, HTMX, or equivalent state.

The action vocabulary must remain truthful: generated, email/WhatsApp opened, copied, and user-reported sent are not delivery, receipt, reading, or response proof. Remove the prototype’s public-response/“gets an answer” implication until a separately approved, moderated publication capability exists. Support records must remain non-linked to the recipient or ask.

The redesign may change public-facing layout, typography tokens, responsive states, locale presentation, and public shared assets only. Admin remains a separate functional surface. All seven locales (`he`, `ar`, `yi`, `ru`, `uk`, `en`, `am`), RTL/LTR behavior, hashed light/dark/system theme assets, and scoped Amharic fonts remain supported; no external prototype font or inline CSP bypass is a data or rollout dependency.
